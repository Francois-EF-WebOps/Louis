# KIT.md — Repository Discovery and First Deliverable Kit

**Status:** scope not yet established. The current README contains only the repository name. This file intentionally does not invent a purpose or prescribe an implementation.

## Read first
1. Review the repository file tree, history, branches, issues and licences.
2. Identify the original problem statement and source artefacts, if any.
3. Record which files are canonical, experimental, generated or obsolete.
4. Search for secrets, private data and third-party material before publishing.

## Requirements artefact
Create a short discovery note before building:
- intended user and problem;
- evidence of intended scope;
- current state and working artefacts;
- constraints, risks and dependencies;
- one smallest useful outcome;
- acceptance criteria and explicit non-goals.

## Low-cost setup
Do not buy tools or add dependencies until the scope and runtime are known. Prefer existing repository tooling and free/open formats. Record any proposed external service, price and data-handling implications before adoption.

## Procedure
1. Inventory existing files and preserve them.
2. Read source/configuration to determine whether an implementation already exists.
3. Ask for clarification in the project issue/decision log if intent cannot be recovered from evidence.
4. Select one reversible, bounded first action.
5. Add a test or verification method before claiming the action is complete.
6. Record actual result, unresolved questions and next owner/action.

## Acceptance
- [ ] Project purpose is evidenced rather than guessed.
- [ ] Existing artefacts and history are preserved.
- [ ] No duplicate project or unnecessary dependencies are introduced.
- [ ] First deliverable has measurable acceptance criteria.
- [ ] No unsupported completion claim is made.
